# שלב 16: אבטחה, בדיקות והעלאה לאוויר

## אבטחה: מה יש במערכת

| שכבה | הגנה |
| --- | --- |
| **נתונים** | Row Level Security על כל טבלה: משתמש רואה ועורך רק את מה ששלו. פעולות רגישות (העתקה, תשלום, ניהול) עוברות דרך פונקציות שבודקות הרשאה בעצמן. 167 בדיקות אוטומטיות מנסות לעקוף את זה |
| **מפתחות** | מפתח Google של השרת ומפתח Supabase הסודי לא מגיעים לדפדפן. מפתח הדפדפן של Google מוגבל לדומיין |
| **קלט** | כל מה שמגיע מהדפדפן נבדק בשרת (אורך, פורמט, טווחים), ובבסיס הנתונים יש עוד שכבת בדיקות |
| **Google** | מיקום של מקום נלקח תמיד מ-Google, לא מהדפדפן. מכסה יומית לכל משתמש על כל סוג קריאה |
| **התחברות** | Supabase Auth: סיסמאות מוצפנות, הגבלת ניסיונות, הודעות שגיאה שלא חושפות אילו אימיילים רשומים, והגנה מפני הפניה לאתר זר אחרי התחברות |
| **תשלומים** | פרטי אשראי לא עוברים אצלנו. ה-webhook נבדק בחתימה, ורכישה נרשמת פעם אחת בלבד |
| **דפדפן** | Content-Security-Policy (רק מקורות מוכרים), HSTS, איסור הטמעה ב-iframe, `nosniff`, ‏Permissions-Policy |
| **AI** | מותר לו רק לסדר מקומות שכבר שמרת. כל תשובה נבדקת, ותשובה לא תקינה מוחלפת באלגוריתם |
| **פרטיות** | מחיקת חשבון מוחקת הכול. הערות אישיות לא משותפות ולא נמכרות. בביקורות מוצג רק השם הפרטי |
