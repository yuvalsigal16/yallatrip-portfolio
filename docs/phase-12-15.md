## החלטות חשובות

| החלטה | למה |
| --- | --- |
| **מסלול שפורסם = עותק קפוא** | בפרסום נוצר עותק נסתר של הטיול. אם היוצר/ת משנה אחר כך את הטיול שלו/ה, מה שכבר נמכר לא משתנה. את העותק הנסתר אי אפשר לראות או לערוך דרך הממשק |
| **תשלומים דרך "מתאם" (provider)** | Stripe לא פותח חשבונות לעסקים שרשומים בישראל. לכן כל הקוד מדבר עם ממשק אחד (יצירת תשלום + webhook), ו-Stripe הוא מימוש אחד שלו. אם העסק רשום בישראל, מוסיפים קובץ אחד לספק ישראלי (PayPlus, Grow, Tranzila) בלי לגעת בשאר |
| **העברות ליוצרים ידנית** | חלוקה אוטומטית בזמן התשלום (Connect) דורשת אימות זהות (KYC) ורישוי. בינתיים הכסף מגיע לפלטפורמה, כל מכירה מתועדת, והמנהל רושם העברה. כך אפשר להתחיל בלי רגולציה מורכבת. **מומלץ לתאם עם רואה חשבון** |
| **כסף באגורות** | מספרים שלמים, בלי שגיאות עיגול. בכל מכירה עמלה + חלק היוצר = המחיר (נאכף בבסיס הנתונים) |
| **העמלה היא הגדרה** | 20% כברירת מחדל, ניתנת לשינוי מדף הניהול (0%–50%). חלה על מכירות מאותו רגע, וכל מכירה שומרת את השיעור שחל עליה |
| **webhook אידמפוטנטי** | הספק עלול לשלוח את אותה הודעה פעמיים. מזהה התשלום ייחודי, לכן נוצרת רכישה אחת. חתימה לא תקינה נדחית (400), ותקלה בשמירה מחזירה 500 כדי שהספק ינסה שוב |
| **הרשאות מנהל נבדקות פעמיים** | הדף מוסתר ממי שאינו מנהל, וגם כל פעולת ניהול בודקת `is_admin()` בבסיס הנתונים |

## הגדרה

1. **המנהל הראשון** (פעם אחת, ב-SQL Editor):
   ```sql
   update public.profiles set role = 'admin'
    where id = (select id from auth.users where email = 'המייל-שלך');
   ```
2. **תשלומים (לא חובה):** ‏`STRIPE_SECRET_KEY` ו-`STRIPE_WEBHOOK_SECRET` ב-`.env.local`. ב-Stripe יוצרים Webhook לכתובת `https://הדומיין/api/payments/webhook` עם האירוע `checkout.session.completed`. בלי המפתחות האלה מסלולים בחינם עובדים, ומסלולים בתשלום מציגים "תיפתח בקרוב".
3. **בדיקה מקומית של תשלום:** ‏`stripe listen --forward-to localhost:3000/api/payments/webhook` (Stripe CLI), וכרטיס בדיקה `4242 4242 4242 4242`.
