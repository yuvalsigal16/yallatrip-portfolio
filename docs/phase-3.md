# שלב 3: בסיס נתונים וארכיטקטורת שרת

## מה בנינו בשלב הזה

את השלד שכל שאר המערכת תעמוד עליו. אין עדיין מסכים. יש:

1. **בסיס נתונים מלא ל-MVP** (Supabase / PostgreSQL): משתמשים, טיולים, ימים, מקומות שמורים, שיבוץ לימים, קטגוריות, יומן המלצות ומכסת שימוש.
2. **שכבת אבטחה בתוך בסיס הנתונים** (Row Level Security): כל משתמש רואה ועורך רק את הטיולים שלו. זה נאכף בבסיס הנתונים עצמו, כך שגם באג בקוד לא יחשוף טיול של משתמש אחר.
3. **שרת שמדבר עם Google בשם המשתמש**: חיפוש מקומות, פרטי מקום, "קרוב אלייך", תמונות, וזמני נסיעה. מפתח ה-API של Google נשאר בשרת בלבד.
4. **בדיקות אוטומטיות**: 47 בדיקות לבסיס הנתונים ו-17 לקוד השרת.

## למה ככה: ההחלטות העיקריות

| החלטה | למה |
| --- | --- |
| האבטחה נאכפת ב-RLS בבסיס הנתונים | שכבת הגנה אחת שלא תלויה בכך שכל קובץ קוד זוכר לבדוק הרשאות |
| ימי הטיול נוצרים אוטומטית מהתאריכים | אם משנים תאריכים, הימים מתעדכנים לבד. מקום שהיה ביום שנמחק חוזר ל"לא משובץ", לא נעלם |
| סטטוס המקום (שמור / במסלול) מתעדכן לבד | מקום ששובץ ליום הופך ל"במסלול", ומקום שהוסר מכל הימים חוזר ל"שמור". "ביקרתי" נקבע רק על ידי המשתמש |
| אי אפשר לערבב בין טיולים | מפתחות משולבים מונעים שיבוץ של מקום מטיול א׳ ביום של טיול ב׳, ומלון שלא שמור באותו טיול |
| מ-Google שומרים רק מזהה ומיקום | תנאי השימוש של Google מגבילים שמירה של כתובות, שעות ודירוגים. אלה נמשכים בזמן אמת. שם המקום נשמר כ"תווית" שהמשתמש יכול לערוך |
| שדה חסר מ-Google הופך ל-null | לא ממציאים. המסך יציג "אין מידע" |
| Field Masks לכל קריאה | מה שמבקשים מ-Google קובע את המחיר. כרטיס מקום מבקש דירוג ושעות (יקר יותר), שמירת מקום מבקשת רק את הבסיס |
| מכסה יומית לכל משתמש | הגנה על התקציב: למשל 60 חיפושי "קרוב אלייך" ביום. המכסה נספרת בבסיס הנתונים ואי אפשר לאפס אותה מהדפדפן |
| **שינוי מהאפיון: בלי PostGIS** | "קרוב אלייך" מגיע מ-Google ולא מבסיס הנתונים, ומרחקים בתוך יום מחושבים בקוד. PostGIS הוא תוסף שאין בו צורך כרגע. אפשר להוסיף אותו בהמשך בלי לשבור דבר |
| **תיקון לאפיון: שכבות תמחור** | דירוג ושעות פתיחה ב-Place Details הם בדרג Enterprise (‏20$ לאלף קריאות מעבר למכסה החינמית), לא Pro כפי שכתבתי באפיון. עדכנתי את מסמך האפיון |
| טבלאות Phase 2 עוד לא נוצרו | יוצרים, רכישות, תשלומים וביקורות יתווספו במיגרציה נפרדת כשנגיע אליהם |

## אילו קבצים נוצרו ומה כל אחד עושה

**בסיס הנתונים**

| קובץ | מה הוא עושה |
| --- | --- |
| `supabase/migrations/20260924000001_init.sql` | כל הטבלאות, הקשרים, הטריגרים והרשאות ה-RLS |
| `supabase/seed.sql` | 12 הקטגוריות (עם הצבעים מהעיצוב) |
| `supabase/tests/01_schema_tests.sql` | 47 בדיקות אבטחה ולוגיקה |

**השרת** (`src/`)

| קובץ | מה הוא עושה |

| `lib/google/fields.ts` | אילו שדות מבקשים בכל סוג קריאה (שולט בעלות) |

| `lib/google/routes.ts` | זמני נסיעה ומרחקים בין תחנות |
| `lib/google/mappers.ts` | ממיר את התשובות של Google למבנה שלנו, בלי להמציא |
| `lib/validation.ts` | בודק כל קלט שמגיע מהדפדפן |
| `lib/api/guard.ts` | דורש משתמש מחובר, סופר מכסה, ומחזיר שגיאות מסודרות בעברית |
| `lib/categories.ts` | איזה סוגי מקומות של Google שייכים לכל קטגוריה |

**כתובות ה-API**

| כתובת | מה היא מחזירה | מכסה יומית |
| --- | --- | --- |
| `GET /api/health` | האם השרת ובסיס הנתונים עובדים | — |
| `POST /api/places/autocomplete` | הצעות בזמן הקלדה | 400 |
| `GET /api/places/{id}?level=basic\|card` | פרטי מקום | 300 |
| `POST /api/places/nearby` | מקומות אמיתיים בקטגוריה סביב נקודה, מהקרוב לרחוק | 60 |
| `GET /api/places/photo?name=...` | תמונת מקום (בלי לחשוף את המפתח) | 300 |
| `POST /api/routes/matrix` | זמן ומרחק בין תחנות (הליכה / תח״צ / רכב) | 100 |

כל הכתובות חוץ מ-health דורשות משתמש מחובר. ההתחברות עצמה נבנית בשלב 4.

## איך מריצים

1. **Supabase:** פותחים פרויקט ב-[supabase.com](https://supabase.com). ב-SQL Editor מריצים את `supabase/migrations/20260924000001_init.sql` ואחריו את `supabase/seed.sql`.
2. **Google Cloud:** מפעילים את Places API (New), Routes API ו-Maps JavaScript API. יוצרים שני מפתחות:
   - מפתח שרת: מוגבל ל-Places API (New) ו-Routes API.
   - מפתח דפדפן: מוגבל ל-Maps JavaScript API ולדומיין של האתר.
   - מומלץ להגדיר התראת תקציב (Budget alert) ב-Billing.
3. **משתני סביבה:** מעתיקים את `.env.example` ל-`.env.local` וממלאים.
4. **הרצה:**
   ```
   npm install
   npm run dev
   ```
   ופותחים את http://localhost:3000
