# שלב 6: מפה ומקומות

## מה בנינו

| יכולת | איך זה עובד |
| --- | --- |
| **מפה אינטראקטיבית** | מפת Google בעברית במסך הטיול, ממורכזת על היעד. אם כבר שמרת מקומות, היא מתרחבת כך שכולם ייראו |
| **חיפוש מקום** | שדה "חפשו מקום ברומא" שצף על המפה. התוצאות מתמקדות באזור שמוצג כרגע במפה |
| **לחיצה על המפה** | לחיצה על כל מקום שמסומן במפה של Google פותחת עליו את הכרטיס שלנו |
| **כרטיס מקום** | תמונה (עם קרדיט לצלם), שם, דירוג, כתובת, פתוח/סגור עכשיו, שעות לכל השבוע, וקישור ל-Google Maps. מה שחסר מופיע כ"אין מידע" |
| **שמירה לטיול** | בוחרים קטגוריה (המערכת מציעה אחת לפי סוג המקום) ולוחצים "+ הוספה לטיול" |
| **סיכות** | כל מקום שמור מקבל סיכה בצבע ובאייקון של הקטגוריה שלו. המלון מסומן בריבוע כהה |
| **קיבוץ סיכות** | מקומות צפופים מתקבצים לעיגול עם מספר, כדי שגם מאות מקומות ייראו מסודר |
| **סינון** | צ׳יפים לפי קטגוריה, רק לקטגוריות שבשימוש, עם מספר המקומות בכל אחת |
| **מקום שמור** | אפשר לשנות קטגוריה, לסמן "זה המלון שלנו", או להסיר מהטיול (עם אישור) |
| **"מה שמרתי"** | רשימה של כל המקומות. לחיצה על מקום פותחת אותו במפה. בשלב 7 נוסיף לרשימה סינון, הערות וסטטוסים |
| **מובייל** | המפה במסך מלא, והכרטיס עולה מלמטה כמו ב-Google Maps |

## למה ככה

| החלטה | למה |
| --- | --- |
| **תיקון אבטחה: רק השרת כותב לטבלת המקומות** | בשלב 3 כל משתמש מחובר יכול היה להוסיף מקום עם קואורדינטות מומצאות, וכל מי שהיה שומר את אותו מקום אחריו היה רואה סיכה במקום הלא נכון. עכשיו השרת בודק את המקום ב-Google, ורק הוא כותב לטבלה, עם מפתח סודי |
| המיקום נלקח מ-Google, לא מהדפדפן | גם בשמירה הדפדפן שולח רק את מזהה המקום. את המיקום השרת מביא בעצמו |
| קואורדינטות מתרעננות אחרי 30 יום | כך מתירים תנאי השימוש של Google |
| הכרטיס מבקש את כל הפרטים, השמירה רק את הבסיס | ככה משלמים את המחיר הגבוה של דירוג ושעות רק כשבאמת מציגים אותם |
| תמונות עוברות דרך השרת | מפתח ה-API לא מגיע לדפדפן, והקרדיט לצלם מוצג כמו ש-Google דורשת |
| המלון הוא מקום שמור רגיל | אותו חיפוש ואותו כרטיס. מקום ראשון שנשמר בקטגוריית "מלון" הופך אוטומטית למלון של הטיול |
| סיכות מותאמות ישירות על מפת Google | לא צריך ספריית מפות נוספת. זה מה שמחייב Map ID (למטה) |
| הסרה בשני שלבים | "להסיר?" ← "כן, להסיר". מונע מחיקה בטעות, בלי חלונות קופצים |

## הגדרות חדשות (חד-פעמיות)

**1. מפתח סודי של Supabase**
- ב-Supabase: ‏Project Settings ← API Keys ← Secret key (או ה-service_role הישן).
- מדביקים ב-`.env.local` תחת `SUPABASE_SECRET_KEY`.
- **חשוב:** המפתח הזה לעולם לא מתחיל ב-`NEXT_PUBLIC_` ולא עולה ל-Git.

**2. מפתח דפדפן של Google Maps**
- ב-Google Cloud: ‏Credentials ← Create API key.
- מגבילים ל-Maps JavaScript API בלבד, ול-HTTP referrers: ‏`http://localhost:3000/*` ובהמשך הדומיין שלך.
- מדביקים ב-`.env.local` תחת `NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY`.

**3. Map ID**
- לבדיקות מקומיות `DEMO_MAP_ID` עובד (הוא כבר מוגדר ב-`.env.example`).
- לפני השקה יוצרים Map ID אמיתי: ‏Google Maps Platform ← Map management ← Create Map ID, מסוג JavaScript / Vector.

**4. חבילות חדשות:** מריצים שוב `npm install`. נוספו `@googlemaps/markerclusterer` ו-`@types/google.maps`.

**5. בסיס הנתונים:** מריצים ב-SQL Editor את `supabase/migrations/20260927000001_places.sql`.

**ידנית, בדפדפן**
1. פותחים טיול לרומא: המפה נטענת בעברית, ממורכזת על רומא, ומופיעה ההודעה "חפשו מקום, או לחצו על כל מקום במפה".
2. מקלידים "פנתיאון" ובוחרים מהרשימה: המפה עוברת למקום, מופיעה סיכה כהה זמנית, ונפתח כרטיס עם תמונה, דירוג ושעות.
3. הקטגוריה המוצעת היא "אטרקציה". לוחצים "+ הוספה לטיול": מופיעה ההודעה "הפנתיאון נוסף לטיול", והסיכה הופכת לירוקה-כחולה.
4. לוחצים על מקום אחר שמסומן במפה של Google (למשל מסעדה): נפתח הכרטיס שלו. שומרים אותו.
5. מופיעים צ׳יפים "הכול 2 · אטרקציה 1 · מסעדה 1". לחיצה על "מסעדה" משאירה רק את הסיכה של המסעדה.
6. מתרחקים עם הזום: שתי הסיכות מתקבצות לעיגול עם "2".
7. שומרים מלון בקטגוריית "מלון": הסיכה שלו ריבועית, וב"מה שמרתי" כתוב "המלון של הטיול".
8. בכרטיס של מקום שמור: משנים קטגוריה, והצבע של הסיכה מתחלף. "הסרה מהטיול" ← "כן, להסיר": הסיכה נעלמת.
9. ב"מה שמרתי" לוחצים על מקום: המפה נפתחת עליו עם הכרטיס שלו.
10. בטלפון: המפה במסך מלא, והכרטיס עולה מלמטה.
11. עם מפתח דפדפן שגוי: מופיעה ההודעה "Google דחה את מפתח המפה".

**מה לא נבדק אצלי:** את המפה עצמה מול Google לא יכולתי להריץ, כי אין לי מפתחות ואין לי גישה ל-npm. את בסיס הנתונים, הלוגיקה והטיפוסים בדקתי. מכיוון שזה השלב עם הכי הרבה קוד שרץ בדפדפן, כדאי לעבור על כל הבדיקה הידנית שלמעלה ולשלוח לי כל שגיאה שמופיעה ב-Console.
